# Claude Code instructions for Looplab

Follow `AGENTS.md` and `docs/AI_AGENT_GUIDE.md` as the authoritative Looplab workflow.
Use the project skill at `.claude/skills/looplab-game-builder/SKILL.md` whenever operating LoopLab. It gives Claude the same project-selection, protected-variation, source-digest, Doctor, acceptance, replay, browser, and export workflow used by Codex.
Run `npm run claude:status` before the first LoopLab session on a machine. Readiness requires the exact executable, scope, arguments, workspace/app URL, connectivity, user-level skill bytes, and an independent fetch of the live app's exact protocol manifest—not merely two matching server names or connected stdio processes. If setup is incomplete or stale and the user has authorized it, run `npm run claude:setup -- "<games-root>"`. Setup reconciles both private user-scoped profiles and atomically synchronizes the repository-owned skill for cross-project Claude sessions; it contains no provider credential.
After setup or a LoopLab upgrade, start the app and run `npm run claude:smoke -- "<games-root>"`. The npm path uses a positional root because Windows npm may consume arbitrary named run-script options; direct Node invocation still accepts `--games-root=...`. The smoke aborts with 0 tokens when the live app/protocol preflight fails. Otherwise it creates and removes a temporary synthetic blank project, reads only one bounded public recipe query on the live surface, and submits one monitored nonpersistent Haiku session through a strict temporary MCP config that advertises exactly those two read-only schemas and ignores installed user/project MCP catalogs. Haiku is an operability-smoke choice only and must never be inferred as the game-generation model; creative Claude Code jobs use their task override or the CLI default and record the resolved model. The smoke never sends a user game brief or shared-project catalog, defaults to a $0.25 CLI budget cap, and requires observed tool calls plus measured usage. Do not resubmit it after a caller timeout; monitor the same process.
When the private local handoff exists, read `claudedocs/codex-to-claude/CURRENT_STATE.md`, `claudedocs/codex-to-claude/PROJECT_KNOWLEDGE.md`, and `claudedocs/codex-to-claude/SHARED_IMPROVEMENT_LOOP.md` before continuing a Codex-started pass. `PROJECT_KNOWLEDGE.md` is the consolidated actionable project model; `SHARED_IMPROVEMENT_LOOP.md` is the complete shared process. Neither is optional background reading.

Key rules:

- Claim the user's pending request, inspect the project, and run Project Doctor before editing.
- Call `get_privacy_report {profile:"production"}` before every provider handoff, shared-project publication, release verification, or export, and rerun it after authored changes. Never send a flagged raw field to a provider for repair. Every creative provider path repeats this check before API/CLI/local-model inference.
- Start live project work with `list_shared_projects` and `mount_shared_project`; treat browser storage as cache. `sourceDigest` is Doctor/gameplay truth; `revisionDigest` is strong whole-document concurrency truth. Save accepted work with `save_shared_project` plus the latest `expectedRevisionDigest` (or `createOnly:true`). On 412, preserve the local draft, call `preview_shared_project_rebase`, inspect every conflict, apply only an exact conflict-free receipt, run gates, and save explicitly—never force overwrite or treat a rebase as evidence.
- In a live session, call `get_agent_presence`, then `register_agent_presence` with one stable Claude ID and renew before the returned heartbeat deadline. Keep the opaque lease token local, leave explicitly when possible, and use `get_work_ledger`—not presence—as durable ownership and handoff truth.
- Treat `project.visualIdentity` as optional canonical authoring guidance, not a fixed aesthetic. Use its four validated headless commands; inherit it by default in provider art; require fresh `referenceConsent:true` for each job that uploads `delivery:image` PNG references; never let a provider rewrite it implicitly; and never treat identity validity or receipts as proof of taste, originality, licensing, geometry, or release readiness.
- Use Full game creation (`creation`) for end-to-end new games; use narrower workstreams only for focused passes.
- Treat the specialist roster truthfully: one selected provider coordinates the AI roles in one response. Project Doctor and Playwright are separate executable gates, not simulated Claude/Codex personas. Return concise coverage receipts for provider roles and never claim browser evidence you did not collect.
- Use stable IDs and atomic JSON command batches. Do not edit generated HTML, atlases, manifests, or version snapshots directly.
- Start gameplay systems from recurring decisions, not a requested verb count. Verb-system v2 allows one deep verb; every additional verb must justify its input and learning cost, work independently when declared standalone, recur before the finale, close a readable decide-act-feedback loop, model recovery/resource flow, and resolve to runtime plus executable-test IDs.
- Author NPC/enemy/companion/cutscene behavior through the strict `actorProgram`, never renderer-owned AI. Start with `suggest_actor_program`, review `get_actor_report`, and set only same-map authored objects/colliders/support/navigation. Require directed-link-connected routes, stable fixed-tick transition priority, actor-state acceptance, replay v8/save v4, and exported actor-state proof.
- Generated art never owns collision. Preserve ground anchors, authored footprints, z/support data, routes, map links, and feature contracts.
- Author repeated terrain through strict map-owned `tileProgram` source. Inspect with `get_tile_program`, `get_tile_program_report`, and bounded `get_tile_region`; use `suggest_tile_program` only to scaffold palette/layer metadata from selected embedded tilesets. Preview every cell edit with `preview_tile_patch`, then apply its unchanged source/program/patch digests through `apply_tile_patch`. Visual layers, terrain signatures, and collision layers are independent; never infer a terrain signature or collision profile from pixels. Missing autotile signatures stay blockers. The same commands and Map Studio Tiles tool are shared by Claude and Codex.
- Author slopes, boundaries, and connected terrain through the strict map-owned `collisionGeometry` contract and the `get`/`report`/`suggest`/`set`/`remove_collision_geometry` command family. Preserve stable point order and right-hand y-down normals, use explicit z ranges for overlapping 2.5D routes, inspect the Collision overlay, and require replay v9 plus deterministic/browser proof. Suggestions may derive only from authored one-way collider tops; never infer collision from pixels.
- Author the standard player lifecycle through `project.gameShell`, not ad hoc renderer flags. Use `get_game_shell`, `get_game_shell_report`, `suggest_game_shell`, `set_game_shell`, and `remove_game_shell`; production requires a valid shell or explicit waiver. Bind win/loss only to deterministic runtime truth, keep lifecycle/preferences outside replay and portable saves, and exercise title/start, pause/resume, settings, win/loss/restart, focus/visibility, audio, reduced motion, and touch-size behavior through exact exported runtime API 2.27 before release.
- Treat `project.maps` order plus `startMapId` as the player-facing route. Use `connect_maps` so every transition is an authored portal targeting an exact spawn.
- For uncertain map geometry, prepare and store one exact map-scoped `spatialLayoutContract`, run the source-bound spatial search, compare its descriptor-distinct projection-compatible candidates, and materialize only one exact candidate digest into the ordinary preview/apply workflow on a protected variation. Preserve mandatory pins and existing evidence; never accept an automatic winner or let generated art own collision.
- Admit third-party assets only through the verified CC0 catalog policy: commercial use, modification, redistribution, and no required attribution must all be explicit.
- Export one self-contained offline-playable HTML file; selected assets are embedded and external runtime requests are forbidden.
- Enforce project schema `1.0.0`, renderer-independent serializable simulation state, a fixed 60 Hz simulation with five-step catch-up cap, and separate p95/dropped-step/encoded/decoded/GPU metrics. Camera and effects remain presentation-only.
- Use the directed movement template when provided. Rails and routes use `add_traversal_path`, `update_traversal_path`, and `remove_traversal_path`; require a fresh E/LOCK capture and keep visual rail art separate from authored traversal geometry.
- Treat continuous worlds, afterimages, parallax, shaders, camera strategies, and streaming as optional plugins. A routed capability is not implementation evidence; require authored data and acceptance tests, and validate the actual runtime seam.
- Canvas and the pinned Phaser browser-script adapter are the release-ready export runtimes. PixiJS and melonJS decision knowledge may improve the design, but their adapters remain knowledge-only until an exact inline UMD/IIFE or tree-shaken IIFE export passes LoopLab's static and hostile-browser gates. Never claim a knowledge-only adapter ships, and never use module-only or CDN runtime references.
- Use Awesome Canvas only to discover candidates; verify the original linked project's license and current code before reuse.
- Run `npm run agent -- audit-html game.html` after export. The audit must reject external resources, runtime network/storage, modules, malformed scripts, missing embedded assets, and credential-shaped values.
- The audit must also reject service workers and Cache API/PWA dependencies. Any selected sidecar must be embedded in the one HTML file.
- Route through the installed 2D specialties exposed by `route_work`; `hbg-loop` is deliberately excluded.
- Run Project Doctor and a Playwright browser playtest after the pass. Call `collect_verification_evidence`, then pass its unchanged structured receipts to `verify_iteration`. Reject regressions and promote only while the Doctor digest and evidence source digest remain current.
- Provider visual critique is optional and requires new explicit user approval for the exact current capture IDs on every submission. Run `capture_visual_review` locally, then call `start_visual_critique` with `consent: true` only for the approved set. Retain the durable job ID, resume with `get_visual_critique_job`, and never duplicate a timed-out request. `get_visual_critique` is source/capture-bound advisory context: it cannot mutate the project, own collision, become Doctor/replay/acceptance/browser/release evidence, choose a winner, or prove aesthetic quality.
- Use `window.looplabAgent` when available; hardened browsers use the documented DOM event bridge at `#looplab-agent-bridge`.
- When looping, preserve the best verified candidate and report real events to the console. A CLI-accepted pass remains a candidate pending browser screenshot evidence; do not call it verified. Do not claim a model call, test, screenshot, or score that did not occur.
- Treat `provider.parity.locked` and its `looplab-provider-parity-receipt/v1` receipt as the operational contract for Codex/Claude interchangeability. Both providers receive the same bounded context and pass plan, frozen evaluation profile, canonical mutation authority, independent gates, ledger behavior, and usage accounting. Transport and creative output may differ; authority and acceptance may not.
- Treat Codex CLI, OpenAI API, Claude Code CLI, and Anthropic API as four failure-isolated provider paths. Missing login, credentials, executable support, network reachability, or a failed run on one path must not block any other ready path. Default jobs automatically retry the unchanged, still-uncommitted proposal through the versioned fallback route; `strict` mode is only for explicit provider locks and comparisons. Always distinguish requested versus actual provider and preserve the complete failover/usage receipt. Image critique may switch transports only inside the consented provider family, and OpenAI image generation remains OpenAI-API-only.
- A saved human playtest is local observation, not evidence. Current `looplab-playtest-session/v2` records semantic transitions at exact fixed simulation boundaries; legacy v1 remains readable but cannot be rounded into replay ticks. Use `preview_playtest_replay` to dry-run the exact tape and inspect source/session/promotion digests plus canonical event-count parity. Only then use `promote_playtest_replay` with all three unchanged digests. Non-reset starts, dropped input/events, mid-run resets, stale source, unsafe fixture replacement, or event mismatch remain blocked. The promoted artifact is an ordinary versioned replay fixture rerun by Doctor and release gates.
- Use canonical `compare_iterations` and require `looplab-candidate-decision/v1` before selecting between preserved candidates. Hard gates constrain feasibility, matching frozen-profile dimensions expose Pareto dominance or tradeoff, and `automaticWinner` is always null. Preview and play both changed candidates, apply the structured judgment prompts and the user's exact vision, then explicitly keep or restore one source-bound parent.
- Select `--evaluation-profile auto|general|platformer|top-down|connected-world|systems`. `auto` resolves once from starting authored truth and stays frozen. Never let provider-generated genre metadata change the metric that judges its own candidate.
- Keep API keys only in the local companion runtime environment or its Windows current-user DPAPI vault. Never place them in browser state, the project, logs, exports, or a response.
- Run `npm run providers:check` before a loop and use only a provider reported as `ready`. The Connection Center can launch Claude or Codex account login and a native Windows API-key prompt without putting credentials in browser state.
- Claude Code provider passes require Claude Code 2.1.205 or newer and use schema-bound stream JSON, a required final `structured_output`, nonpersistent safe-mode sessions, `dontAsk` permissions, and a task-scoped tool surface. Prompt/game passes receive no tools; research receives only WebSearch and WebFetch. Never fall back to free-form text and call it equivalent.
- Treat capability harvesting as permanent: a reusable hard-won fix must become a canonical LoopLab capability plus a regression and rejected-case replay, not only a patch to the current game.

Non-interactive entry point:

```powershell
npm run loop -- --provider claude --project game.loop.json --iterations 5 --goal "the user's brief"
```

Direct Anthropic API entry point (requires `ANTHROPIC_API_KEY`):

```powershell
npm run loop -- --provider anthropic --project game.loop.json --iterations 5 --goal "the user's brief"
```
